# Методология прогноза энергопотребления

## Целевая метрика

Прогноз строится для общего месячного входа по техническому балансу в кВт·ч.
Дневная кривая распределяет тот же объём по календарным дням. Это исключает
смешивание общего входа с отдельными уровнями подстанций и счётчиков.

## Формула

Для каждого дня:

```text
E_day = E_calendar + E_weather + E_events
```

Где:

- `E_calendar` — последний месячный техбаланс, нормированный на число дней,
  умноженный на взвешенный тренд и распределённый по профилю дней недели;
- `E_weather` — поправка HDD/CDD-регрессии относительно климатической нормы;
- `E_events` — сумма датированных изменений мощности.

Тренд использует до трёх последних месячных изменений с большим весом свежих
данных и ограничивается диапазоном от -15% до +15%.

Погодная модель оценивает два коэффициента:

```text
HDD = max(0, 18 - T_mean)
CDD = max(0, T_mean - 22)
```

Коэффициенты показывают изменение кВт·ч на один градусо-день холода или жары.
Дневная погодная поправка ограничена 20% базовой нагрузки, чтобы короткая
история не создавала физически неправдоподобные скачки.

Операционное событие считается так:

```text
E_event = direction * capacity_kW * 24h * utilization
```

`direction` равен `-1` для остановки и снижения нагрузки и `+1` для ввода
мощности. Поправка применяется только между датами начала и окончания.

## Погодные источники

- до 16 дней: Open-Meteo Best Match;
- дальний горизонт: ECMWF EC46 / SEAS5;
- историческая калибровка и климатическая норма: ERA5;
- исторический backtest: архивный ECMWF IFS run на дату cutoff.

Фактическая погода после cutoff не используется для ретроспективного прогноза.
Если внешний API недоступен, расчёт продолжается без погодной поправки и
помечает погодный слой как недоступный.

Координаты задаются переменными:

```text
ENERGOPULSE_FORECAST_LOCATION_NAME
ENERGOPULSE_FORECAST_LATITUDE
ENERGOPULSE_FORECAST_LONGITUDE
ENERGOPULSE_FORECAST_TIMEZONE
```

По умолчанию используется площадка Жанажол в Актюбинской области.

## Контроль качества

Скользящий месячный backtest прогнозирует каждый доступный месяц только по
предыдущему. MAPE влияет на коридор неопределённости и показатель уверенности.
При росте истории следующий шаг — backtest по фиксированному cutoff и сравнение
гибридной модели с сезонным naive baseline.

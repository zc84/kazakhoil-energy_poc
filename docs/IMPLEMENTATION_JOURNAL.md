# Журнал изменений приложения

Журнал ведется только для изменений в приложении: фич, пользовательских сценариев, API, бизнес-логики, данных и поведения интерфейса. Новые записи добавляются сверху и фиксируют, что изменилось, как было и как стало.

## 2026-08-30 - Каталог 10 точек, устранение двойного учёта, сегментированные пики

- **Фича:** экраны «Тех. баланс», «Ежедневное потребление» и «Пики и аномалии» приведены к продуктовому каталогу из 10 внутренних точек КОА (Алибекмола, Кожасай) и внешней линии, устранено двойное суммирование повторяющихся приборов учёта, добавлены среднее суточное потребление, сегментация «Все / КОА / Субпотребители» и объяснение показателя полноты дневных данных.
- **Что сделал:**
  - добавил каталог 10 точек и внешней линии с alias-ами, проверенными по заголовкам всех 7 файлов техбаланса и суточных сводок за январь-июль;
  - заменил список произвольных технических секций на этот каталог в ответах `technical-balance` и `daily-consumption`, с явным «Требует уточнения» для нераспознанных заголовков и `сети данных` для точек без источника в загруженном файле;
  - нашёл и исправил конкретное двойное потребление: один физический прибор, повторно перечисленный в книге (например, входы 110 кВ, повторённые в итоговом блоке в конце техбаланса), теперь считается один раз в сумме по точке, но обе строки остаются видимыми в таблице с пометкой `is_duplicate`/`duplicate_of_row` для прослеживаемости;
  - исправил ежедневную сводку: заголовки подстанций внутри дневных листов не считывались вовсе (`active_substation` всегда оставался `None`), из-за чего весь суточный breakdown уходил в одну группу; теперь заголовок читается по той же логике, что и в техбалансе;
  - убрал KPI «Строки учёта», заменил на «Основные точки: N/10»;
  - убрал вводящий в заблуждение показ «% от общего входа» для распределения по точкам (точка и её дочерние линии/счётчики после её заголовка суммируются вместе и физически не образуют взаимоисключающие доли одного входа) — показаны абсолютные кВт·ч с пояснением;
  - на экране «Пики и аномалии» добавил KPI «Среднее за день», переключатель «Все/КОА/Субпотребители» (оценка по доле техбаланса за месяц, суточного разреза по субпотребителям в исходных данных нет), и заменил «Полнота дневных данных» с одного числа на факт/ожидание и процент с расшифровкой в подсказке.
- **Как было:** «Тех. баланс» показывал top-10 произвольных технических секций вместо каталога, один и тот же прибор мог войти в две разные секции с одинаковым значением (подтверждено на реальном июльском файле: счётчик 51555191 отображался и под «ПС-110/35/6кВ», и под «БКНС Кожасай» с одинаковым расходом), ежедневная сводка не показывала подстанции вовсе, «Строки учёта» не несло продуктового смысла, «Полнота дневных данных» была одним необъяснённым числом.
- **Как стало:** оба экрана показывают одинаковый каталог 10 точек + внешняя линия, повторный прибор учитывается один раз, ежедневный breakdown восстановлен, «Основные точки: 8/10» на реальных июльских данных, «Полнота дневных данных: 181/212 · 85%», сегментированные пики и среднее за день на «Пики и аномалии».
- **Проверка:** `PYTHONPATH=. ./.venv/bin/python -m unittest discover -s apps/api/tests -v` — 23 теста OK (добавлен тест на дедупликацию повторного прибора и на резолв каталога); `npm run build` — успешно; ручная проверка в браузере на реально загруженном июльском техбалансе и суточной сводке — каталог, дедупликация и сегментированные пики подтверждены на живых данных.
- **Осталось нерешённым (см. отчёт клиенту и раздел 3.3/W2 плана):** для «РП-6 БКНС-Алибекмола», «РП-6 Газзавод» и внешней линии «Южный Жанажол» в загруженных файлах данные/ нет заголовка, однозначно определяющего эту точку — они показаны как каталожные точки без источника, а не смоделированы произвольно; суммы внутри одной каталожной точки по-прежнему смешивают уровень входа и уровень дочерних линий/счётчиков (нужна явная граница агрегации по W2.3, иначе сумма по точке не равна её доле от общего входа).

## 2026-08-30 - Определение периода и активные версии импорта

- **Фича:** загрузка Excel-файлов с определением календарного периода и защитой от повторной публикации одного набора.
- **Что сделал:** добавил извлечение дат ежедневных листов из заголовка книги, явные предупреждения о несовпадении имени листа и даты, semantic fingerprint, период импорта, активную версию и supersede-политику при публикации.
- **Как было:** период дашбордов определялся только по имени файла; июльская книга без года выпадала из фильтров, а повторные версии одного периода могли участвовать в расчетах одновременно.
- **Как стало:** период определяется по содержимому книги с fallback на имя файла, июль распознается как июль 2026, конфликтные и дублирующиеся даты видны как issues, а публикация новой версии деактивирует предыдущую и блокирует идентичное содержимое.
- **Проверка:** `PYTHONPATH=. ./.venv/bin/python -m unittest discover -s apps/api/tests -v` — 22 теста OK; `npm run build` — успешно; read-only прогон 19 книг из `данные/` распознал 8 техбалансов, 4 акта и 7 ежедневных сводок, fingerprint уникален для 18 наборов; зафиксированы ожидаемые проблемы мая и июня.

## 2026-08-30 - Подстанции в техническом балансе

- **Фича:** экран `Тех. баланс` и виджет распределения по подстанциям после загрузки техбаланса.
- **Что сделал:** добавил динамическое распознавание заголовков подстанций и участков в листе `Тех.Учёт`, построил распределение техбаланса по распознанным подстанциям и синхронизировал график с легендой top-10.
- **Как было:** backend опирался на несколько жестко заданных диапазонов строк, из-за чего большинство строк техбаланса получали `substation = null`, а виджет подстанций наследовал неполный разрез внешних организаций.
- **Как стало:** строки техбаланса получают контекст ближайшего распознанного заголовка, API `technical-balance` возвращает полный набор найденных групп, а интерфейс показывает 10 крупнейших подстанций/участков в диаграмме и легенде.
- **Проверка:** `PYTHONPATH=. ./.venv/bin/python -m unittest tests.test_dashboard_daily_consumers tests.test_dashboard_endpoints` прошел: 14 тестов OK; `npm run build` прошел; live API `/api/v1/dashboards/technical-balance` возвращает 17 групп, top-10 видимы в UI, строк без `substation` в таблице 0 из 340.

# Руководство пользователя «ЭнергоПульс»

«ЭнергоПульс» помогает загрузить энергетические отчёты, проверить качество
данных, изучить энергобаланс и аномалии, настроить потребителей и сформировать
прогноз с учётом погоды.

## 1. Рекомендуемый порядок работы

1. Откройте **«Исходные данные»**.
2. Загрузите ежедневные сводки и технические балансы.
3. Проверьте статусы файлов и замечания.
4. Изучите **«Энергобаланс»** и **«Пики и аномалии»**.
5. В разделе **«Потребители»** назначьте погодные регионы.
6. Откройте **«Прогноз»** и при необходимости добавьте производственные события.
7. Используйте AI-чат для вопросов по загруженным данным.

Для первого расчёта достаточно ежедневной сводки за один месяц. Технический
баланс добавляет структуру собственного и внешнего потребления и повышает
надёжность прогноза.

## 2. Загрузка исходных файлов

Перейдите в **«Исходные данные»** и нажмите **«Загрузить файлы»**. Можно выбрать
сразу несколько файлов `.xlsx` или `.xls`.

Система распознаёт два основных типа:

- **ежедневная сводка** — суточная динамика, контрольные вводы, точки нагрузки,
  пики и аномалии;
- **технический баланс** — месячный энергобаланс, собственное потребление,
  сторонние организации и сверка итогов.

После загрузки проверьте:

- название и тип набора данных;
- количество принятых строк;
- статус обработки;
- число ошибок и предупреждений;
- протокол замечаний для конкретного файла.

Файл со статусом **«Загружен»** и без ошибок уже участвует в расчётах.

## 3. Разделы системы

### Сводка

Стартовый экран показывает:

- сколько файлов загружено и прошло проверку;
- доступны ли суточные данные и энергобаланс;
- последнюю загрузку;
- быстрые переходы к аналитике и исходным данным.

Сразу после загрузки данные могут появиться не мгновенно. Дождитесь окончания
синхронизации в левом нижнем углу.

### Энергобаланс

Если загружена только ежедневная сводка, система показывает предварительный
суточный баланс по контрольным вводам.

После загрузки технического баланса становятся доступны:

- общий месячный отпуск;
- собственное потребление КОА;
- внешнее потребление;
- доли и динамика по месяцам;
- входы, отходящие линии и крупнейшие потребители;
- качество расчёта и расхождения с итогами исходного файла.

Важно: ПС Кенкияк, ПС Эмба и Южный Жанажол в суточном ряду — это источники
поступления по контрольным вводам, а не внешние потребители.

### Пики и аномалии

Раздел доступен после загрузки ежедневной сводки. Здесь можно:

- выбрать месяц;
- увидеть пиковый день;
- сравнить нагрузку по дням;
- найти резкие изменения и отрицательные интервалы;
- оценить вклад контрольных вводов.

### Потребители

Система использует наиболее подробный доступный источник:

- сторонние организации из технического баланса;
- точки нагрузки из ежедневной сводки, если техбаланса нет.

Для каждого потребителя назначьте погодный регион. Это необходимо, чтобы
прогноз учитывал температуру в месте потребления.

Доступные действия:

- выбрать регион вручную в строке потребителя;
- нажать **«Остальным — Актобе»**, если все ненастроенные объекты действительно
  относятся к Актюбинской области;
- нажать **«Сбросить регионы»** для повторной настройки;
- нажать **«Обновить»** после изменения состава исходных данных.

Небольшим объектам система может предварительно назначить центральный погодный
регион. Проверьте эти назначения перед использованием прогноза.

### Прогноз

Страница доступна после появления энергетических данных.

Если не всем потребителям назначены регионы, внутри страницы появится экран
**«Подготовка прогноза»**. Он показывает:

- сколько потребителей уже настроено;
- какие потребители ещё требуют региона;
- кнопку **«Перейти к потребителям»**.

После назначения последнего региона прогноз формируется автоматически.

На готовом экране доступны:

- прогноз следующего месяца и ожидаемый диапазон;
- надёжность расчёта;
- фактический и прогнозный суточные ряды;
- температура и погодные аномалии;
- фильтр по потребителям;
- сценарии «Экономный», «Базовый» и «Пиковый»;
- добавление остановок, снижения или ввода мощности;
- экспорт таблицы в CSV;
- описание методики и источников данных.

Если технического баланса нет, прогноз строится по суточной истории, а его
максимальная оценка надёжности ограничивается. После добавления техбаланса
система автоматически использует его как более полную основу.

### Месячная сверка

Раздел сопоставляет ежедневные сводки и технические балансы за одинаковые
месяцы. Для корректной сверки загрузите оба типа файлов за один период.

### Исходные данные

Используйте этот раздел для:

- добавления файлов;
- просмотра журнала загрузок;
- проверки распознанного типа и периода;
- просмотра протокола ошибок и предупреждений;
- повторной проверки исходных данных.

## 4. AI-чат и инсайты

### Настройка

1. Откройте раздел **«OpenAI»**.
2. Укажите API-ключ.
3. Выберите модель.
4. При необходимости отредактируйте роль и правила энергоаналитика.
5. Сохраните настройки.

Ключ хранится на backend и не возвращается целиком в браузер.

### Использование

Откройте AI-чат кнопкой в правом нижнем углу. Примеры вопросов:

- «Какой месяц имеет максимальное потребление?»
- «Какой контрольный ввод дал наибольший вклад?»
- «Кто крупнейший внешний потребитель в марте?»
- «Какие дни были пиковыми?»
- «Почему прогноз имеет такую надёжность?»
- «Какие проблемы качества данных влияют на вывод?»

AI отвечает только по нормализованным данным системы. Количество строк и листов
файла не считается показателем потребления. Если данных недостаточно, AI должен
указать, какого файла, периода или показателя не хватает.

## 5. Как читать статусы

| Состояние | Что означает | Что делать |
|---|---|---|
| Подключено | Frontend получает данные от API | Можно работать |
| Синхронизация | Выполняется начальная загрузка данных | Подождать несколько секунд |
| Нет соединения | API недоступен | Проверить backend и сеть |
| Загружен | Файл распознан и участвует в расчётах | Проверить замечания |
| С ошибкой | Файл требует проверки | Открыть протокол |
| В работе | Потребителю не назначен регион | Выбрать погодный регион |
| В норме | Потребитель настроен | Дополнительных действий нет |

## 6. Типовые проблемы

### Энергобаланс есть, а потребителей нет

Нажмите **«Обновить»** в разделе «Потребители» или обновите страницу. Если
список остаётся пустым, проверьте, содержит ли файл отходящие точки нагрузки
или лист сторонних организаций.

### Прогноз не сформирован

Откройте «Прогноз» и посмотрите список ненастроенных потребителей. Назначьте им
погодные регионы. Также убедитесь, что есть ежедневная история хотя бы за один
месяц.

### После загрузки ничего не изменилось

1. Дождитесь статуса **«Подключено»**.
2. Проверьте файл в «Исходных данных».
3. Нажмите «Обновить» на нужной странице.
4. При необходимости выполните жёсткое обновление браузера:
   `Ctrl + Shift + R` или `Cmd + Shift + R`.

### AI использует непонятный технический термин

Уточните вопрос и укажите нужную бизнес-метрику. Пользовательский ответ не
должен содержать внутренние имена полей или идентификаторы; если они появились,
зафиксируйте текст ответа для диагностики.

## 7. Очистка данных

Кнопка **«Очистить данные»** находится внизу левого меню. Она удаляет:

- все загрузки и результаты обработки;
- строки промежуточного хранения;
- протоколы проверки;
- AI-инсайты и историю чата;
- сохранённые исходные файлы.

Действие необратимо. Используйте его только для полного начала работы заново.

## 8. Локальный запуск для администратора

Backend:

```bash
uv run --project apps/api uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Frontend в отдельном терминале:

```bash
npm install
npm run dev -- --host 127.0.0.1
```

Адреса:

- приложение: `http://127.0.0.1:5173`;
- API: `http://127.0.0.1:8000`;
- проверка API: `http://127.0.0.1:8000/healthz`.
